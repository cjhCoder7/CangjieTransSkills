# 执行轨迹模板

## 1. 文档目的

本模板用于规范 Agent 在一次具体执行中产生的全链路日志，覆盖：

- 翻译任务输入；
- 触发的 Skill；
- 检索动作；
- 生成代码；
- 编译与运行；
- 报错分析；
- 修复与重试；
- 最终结论。

它不是样本总体总结，而是 **一次 run 的原子级执行记录**。

换句话说：

- `sample-record-template.md` 解决“这个样本整体是否有效”；
- 本模板解决“这一次执行到底做了什么、为什么成功或失败”。

## 2. 使用规则

- 每次独立执行建议创建一份轨迹文件；
- 文件名建议使用：

```text
trace-<date>-<sample-or-task>-run-<nn>.md
```

**示例**：

```text
trace-2026-03-26-ui-layout-run-01.md
trace-2026-03-26-preferences-run-02.md
trace-2026-03-27-telegram-chatlist-run-01.md
```

- 每轮编译失败、修复、重试都必须留下记录；
- 不要只记录最后一次成功结果；
- 若一次 run 包含多个子任务，应明确拆分阶段，而不是混成一个段落；
- 关键日志、命令、报错摘要必须原样或高保真摘录。

## 4. 建议实践

### 4.1 轨迹文件应该短周期生成

建议每进行一次实质性的“翻译 -> 构建 -> 观察 -> 修复”闭环，就生成或更新一次轨迹文件，而不是在最后回忆式补写。

### 4.2 轨迹文件与样本记录必须互相引用

- 样本记录用于总结；
- 轨迹文件用于证明；
- 没有轨迹的样本记录，可信度不足；
- 没有样本记录归档的轨迹，也容易失去上下文价值。

### 4.3 轨迹文件是后续 Pipeline 评估的基础数据

后续分析“哪些 Skill 有效、哪些检索动作无效、哪些错误反复出现”时，主要依赖本模板沉淀的数据。
