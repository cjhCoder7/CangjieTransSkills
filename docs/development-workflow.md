# 开发与验证流程建议

## 1. 开始任务前

- 先阅读 `AGENTS.md`；
- 再阅读 `/.claude/mission-control.md` 与 `/.claude/status/current-phase.md`，确认当前阶段、命令入口与主要阻塞；
- 再对照 `docs/requirements-baseline.md` 与 `docs/evaluation-criteria.md`，确认本次任务的最低要求与完成口径；
- 明确当前任务属于文档整理、Skill 构建、样本验证、工程翻译，还是 `.claude` / 路由层维护；
- 如果依赖外部仓库或资料，先记录来源与版本；
- 如果依赖未获批的权限，先写清楚阻塞点与替代方案。

## 2. 执行任务时

- 优先做最小闭环，不一次性扩展太大范围；
- 尽量留下输入、输出、命令、日志与验证结果；
- 区分“已验证事实”和“基于资料推断”；
- 需要引入脚本时，先确保脚本输入输出明确、路径清晰、可重复执行。

## 3. 完成任务后

- 更新相关文档；
- 如果形成了新的约束、目录规范或经验结论，回写 `AGENTS.md`；
- 如果产出实验结果或样本结论，沉淀到 `research/`、`docs/reports/` 或 `artifacts/`；
- 如果引入外部代码，补充来源说明文件。

## 4. 推荐工作顺序

1. 文档整理与目标澄清；
2. Skill 结构设计；
3. 样本筛选；
4. 翻译实验；
5. 编译 / 测试 / 运行验证；
6. 结果回写与问题归档。

## 5. 当前验证原则

- 能编译优先于“看起来合理”；
- 能运行优先于“代码量多”；
- 小样本稳定优先于全量铺开；
- 可追溯优先于一次性产出；
- 不在仓库中保存明文密钥。
