# 仓颉流程到 LoopX Todo 的映射

本文件用于规划 Todo 粒度。实际状态转换、参数和命令模板以当前 LoopX CLI 输出为准。

## 应用迁移

| 顺序 | Todo 阶段 | 完成证据 |
| --- | --- | --- |
| 1 | 分流、源项目与目标项目摸底 | 项目类型、源语言、范围和环境结论 |
| 2 | 资源枚举、复制和引用映射 | 资源清单、原名到新名映射、缺失资源列表 |
| 3 | 架构与高风险语义决策 | 已确认的模块边界；未确认项进入用户 Gate |
| 4 | 按依赖拓扑分批翻译 | 每批代码和对应的构建/测试结果 |
| 5 | 应用构建 | HAP 路径及成功结果，或可复现失败摘要 |
| 6 | UI 与关键交互验证 | 控件树/截图结论、断言结果和修复闭环 |
| 7 | 经验回写与最终验收 | 经验索引、差异报告、未解决项和结案检查 |

小项目可以合并第 3、4 阶段；大项目按功能模块拆分第 4 阶段。不要按单个文件创建 Todo。

## 库迁移

| 顺序 | Todo 阶段 | 完成证据 |
| --- | --- | --- |
| 1 | 分流与源项目摸底 | lib 判定、语言/工具链/测试事实 |
| 2 | 公共 API 与依赖策略 | API 对照表、每项依赖的明确决策 |
| 3 | cjpm 骨架和高风险决策 | 可解析骨架、`decisions.md`、必要用户 Gate |
| 4 | 按依赖拓扑分批翻译 | 每批实现及对应的 `cjpm build` 结果 |
| 5 | consumer 冒烟和测试迁移 | 公共 API 可见性、功能测试结果 |
| 6 | 经验回写与最终验收 | 构建产物、经验索引、差异与遗留项 |

## 独立构建或测试

通常只创建一个有界 Todo：确认项目类型和环境后执行构建/测试，写回命令结果、产物和失败摘要。修复编译错误属于同一 Todo 的小范围迭代；若修复扩展为多个独立模块，再拆 successor。

## 独立 UI 验证

通常分为两个阶段：

1. 设备/HAP/采集环境确认；
2. 关键页面和交互验证、问题修复及复验。

设备或 HAP 缺失使用用户 Gate。每次单步交互的中间截图不是独立 Todo。

## 原始文档下载

列出可用文档源是只读查询，不创建 Todo。实际下载通常只创建一个有界 Todo：确认文档源、语言、网络权限和目标路径，执行后验证 `index.json` 及文件统计。网络或写入权限缺失时使用用户 Gate；原始文档和下载日志保持 Git 忽略。

## Todo 建模约束

- 同一优先级保持规划顺序和写入顺序一致。
- Agent Todo 必须有可观察完成条件；“继续处理”“完善一下”不是合格目标。
- 用户选择只阻塞依赖该选择的 Todo。
- 构建、测试、UI 验证是交付证据，不以“代码已写完”代替。
- 原始证据放在忽略目录，LoopX 状态只记录摘要、摘要哈希或稳定引用。
