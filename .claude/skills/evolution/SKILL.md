# 仓颉语言开发经验总结

> 开发过程中遇到非显而易见的问题并解决后，将经验记录到对应分类中。

## LoopX 关联规则

当经验来自 LoopX 管理的翻译、构建或 UI Todo 时：

- 只有问题已复现、方案已通过对应构建/测试/UI 复验后才写入经验库；
- 在 Todo 结果中记录经验文件的稳定相对路径和一句话结论，不复制整段经验正文；
- 未解决或未经验证的判断留在 Todo 风险、用户 Gate 或 successor 中，不污染长期知识库；
- 经验回写完成后再结束对应阶段，避免结案后遗漏知识沉淀。

独立的只读经验查询不需要创建 LoopX Goal；主动修改经验文件属于操作型请求，需由 `cangjie-loopx-management` 管理。

## 经验记录规范

### 何时记录

解决了一个**非显而易见**的问题后，将经验追加到对应分类中：
- 文档未提及或描述不清的行为
- 需要特定组合才能工作的配置
- 容易混淆的 API 或概念
- 性能陷阱或反直觉的行为
- 从其他语言迁移时的等价写法差异

### 文件组织

每个分类目录下有一个 `README.md` 作为索引，经验按主题拆分为独立文件（如 `syntax.md`、`arkui.md`）。新增经验时：
1. 若属于已有主题文件，直接追加
2. 若属于新主题，创建新文件并更新该目录的 `README.md` 索引

**不预先创建空文件**，遇到对应问题时再创建。

### 单条经验格式

```markdown
## [经验标题]

**问题**: 描述遇到的现象或报错信息
**原因**: 根因分析
**解决方案**:
具体修改步骤或代码示例
**相关文档**: 指向 cangjie-kernel / cangjie-harmony 中的具体文档（如有）
```

### 记录原则

1. 一条经验解决一个问题
2. 先写问题现象，方便后续通过报错信息检索
3. 附最小复现代码（如果与特定代码模式相关）
4. 保持简洁，经验记录不是教程
